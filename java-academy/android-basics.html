18.2Gradle and the version catalog

Gradle compiles your Java, merges resources and manifests, runs annotation processors (Room), converts bytecode to DEX, and packages and signs the APK. Modern projects write build scripts in the Kotlin DSL (.gradle.kts) — you don't need to know Kotlin to read them. The module script is where you'll spend most time:

  • After editing a build file, click Sync Now (or the 🐘 elephant icon). Android Studio's Build tool window shows errors; the first red line is usually the real one.
  • implementation = needed to compile and run the app; testImplementation / androidTestImplementation = tests only; annotationProcessor = a code generator that runs inside javac (Room uses it in lesson 21).
  • Dependencies come from Google's Maven (AndroidX, Material) and Maven Central — repositories declared in settings.gradle.kts.
  • Useful tasks in the Terminal: ./gradlew assembleDebug, installDebug, testDebugUnitTest, lintDebug, app:dependencies.

18.3Which Java can you use on Android?

Two different questions hide here, and mixing them up crashes apps:

Language features

Syntax like lambdas, var, switch expressions, text blocks, records and instanceof patterns. These are compiled away by javac and D8, so with JavaVersion.VERSION_17 they work on every device your minSdk allows.

Library APIs

Methods of java.* classes, like String.strip() or List.of(). These must exist in the phone's runtime, which depends on its Android version — not on your JDK.

  1. Android Lint underlines such calls in the editor and fails ./gradlew lintDebug with a NewApi error. Run it in CI — the Spendly project does.

18.4The manifest

AndroidManifest.xml is the app's declaration to the operating system: which components exist, which one launches, which permissions are needed. Android can only start components listed here.

The four component types are Activity (a screen), Service (background work without UI), BroadcastReceiver (reacts to system events) and ContentProvider (shares data). Most apps are mostly activities; WorkManager (lesson 21) replaces most services.

18.5The Activity lifecycle

You never call new MainActivity(). Android creates activities and calls lifecycle methods as the user moves around — and may destroy them at any time to save memory or when the configuration changes (rotation, dark mode, language).

🔄
Rotation destroys your Activity

Every field of the old Activity object is gone. Small UI state survives via onSaveInstanceState; screen data should live in a ViewModel, which survives configuration changes (lesson 20). Views with an android:id (like EditText) save their own text automatically.

18.6Resources and the R class

Never hard-code user-visible text, colours or sizes in Java. Put them in res/; the build generates the R class with an int ID for each. Android picks the best variant at runtime using qualifiers in folder names.

FolderUsed when…
values-vi/strings.xmlthe device language is Vietnamese
values-night/themes.xmldark mode is on
layout-land/landscape orientation
values-sw600dp/the smallest screen width is ≥ 600 dp (tablets)
drawable-v31/Android 12 (API 31) and newer

Sizes use dp (density-independent pixels) for layout and sp (scales with the user's font size) for text — never raw px.

18.7Intents: moving between screens and apps

An Intent is a message asking Android to start a component. Explicit intents name the class; implicit intents describe an action and let the system pick an app.

18.8Logcat, Toast and Context

  • Logcat (bottom tool window) shows logs from the device. Write with Log.d(TAG, "msg") (debug), Log.i, Log.w, Log.e(TAG, "msg", exception). Filter with package:mine level:debug tag:MainActivity. Crashes appear as FATAL EXCEPTION with a clickable stack trace.
  • Toast — a short message: Toast.makeText(this, R.string.saved, Toast.LENGTH_SHORT).show();. For messages with an action (Undo), use a Material Snackbar (lesson 19).
  • Context is your handle to the system: resources, preferences, starting activities, system services. An Activity is a Context tied to one screen; getApplicationContext() lives as long as the process. Pass the application context to anything long-lived (databases, repositories) to avoid leaking screens.
  • A custom Application subclass (declared with android:name in the manifest) is created once per process before any activity — the right place to build app-wide objects such as the database. Spendly's SpendlyApp does exactly that.

18.9Exercises

Exercise 1 — Lifecycle detective Easy

Add the logging lifecycle methods above to your HelloAndroid app. Predict, then verify in Logcat, the callbacks for: pressing Home; returning; rotating; pressing Back. Which sequence differs between rotation and Back?

Home: onPause → onStop. Return: onRestart → onStart → onResume. Rotation: onPause → onStop → onDestroy → onCreate → onStart → onResume. Back: onPause → onStop → onDestroy (no onCreate: the user left).

Exercise 2 — A counter that survives rotation Medium

Add a button that increments a counter shown in a TextView. Rotate the phone: the count resets. Fix it with onSaveInstanceState, then test “Don't keep activities” in Developer options.

Exercise 3 — Translate the app Challenge

Move every hard-coded string into strings.xml (Android Studio: Alt+Enter → Extract string resource). Then open Translations Editor, add Vietnamese, translate, and switch the emulator's language to check. Which file did the editor create?

res/values-vi/strings.xml. Missing translations fall back to values/strings.xml.
