Lesson 05 · Java Fundamentals

Methods

Methods give a name to a piece of logic so you can reuse it, test it and reason about it. Learn how to declare them, how arguments are really passed, overloading, varargs, scope and recursion.

⏱ 45 min🎯 Beginner🧩 Prerequisite: lesson 04

You will be able to

  • Declare methods with parameters and return values
  • Overload methods safely
  • Explain Java's pass-by-value semantics
  • Accept a variable number of arguments
  • Reason about scope and lifetime
  • Write and debug recursive methods

5.1Declaring and calling methods

A method has a signature — modifiers, return type, name and parameter list — and a body. For now all our methods are static: they belong to the class and are called without creating an object (lesson 07 introduces instance methods).

Parameters
The variables in the declaration (unitPrice, quantity).
Arguments
The actual values passed in a call (3.50, 2).
return
Ends the method immediately and produces its value. A non-void method must return a value on every path — the compiler checks.

5.2Early returns and guard clauses

Handle special cases first and return early. The “happy path” then reads without deep nesting.

5.3Overloading

Several methods may share a name if their parameter lists differ (number or types). The compiler picks the best match at compile time. The return type alone is not enough to overload.

5.4Java is always pass-by-value

When you call a method, each parameter receives a copy of the argument. For a primitive, that's a copy of the number. For a reference, it's a copy of the arrow — both arrows point to the same object. So a method can change the object, but it cannot make the caller's variable point somewhere else.

🏠
Analogy

Passing a reference is like giving someone a photocopy of your house address. They can go there and repaint the door (mutate the object). If they scribble a different address on their copy, your copy still points to your house.

5.5Varargs: any number of arguments

A last parameter written Type... name accepts zero or more arguments; inside the method it's an array. String.format, List.of and printf all use varargs.

5.6Scope and lifetime

A local variable exists from its declaration to the end of the enclosing { } block. Parameters are locals of the method. Every call gets fresh copies — that's what makes recursion work.

5.7Recursion

A recursive method calls itself on a smaller version of the problem. It needs a base case that stops the recursion; otherwise each call adds a frame to the call stack until a StackOverflowError.

🐞
Watch it in the debugger

Set a breakpoint on the return line in Android Studio and start Debug (🐞). The Frames panel shows one entry per active call — the call stack made visible. Step with F8 (over) and F7 (into).

5.8Designing good methods

  • Do one thing and name it with a verb: calculateTax, isValidEmail, formatPrice.
  • Keep them short — if you need a comment to separate “parts”, extract each part into its own method (Ctrl+Alt+M / ⌘+⌥+M = Extract Method).
  • Few parameters — more than three or four is a hint to introduce a class or record (lesson 09).
  • Prefer pure methods: output depends only on inputs, no hidden side effects. They're trivial to test.
  • Return, don't print: a method that returns a value can be reused by a UI, a test or a server; one that prints cannot.

5.9Exercises

Exercise 1 — Leap year Easy

Write static boolean isLeapYear(int year) (divisible by 4, except centuries, except every 400 years) and test it with 1900, 2000, 2024 and 2025.

Exercise 2 — Greatest common divisor Medium

Implement Euclid's algorithm recursively: gcd(a, 0) = a, otherwise gcd(a, b) = gcd(b, a % b). Then overload gcd(int... numbers) to work for any count of numbers.

gcd(48, 18) picks the two-parameter method: an exact match beats varargs.

Exercise 3 — Fast power Challenge

Write static long power(long base, int exp) using exponentiation by squaring: xn = (xn/2)² for even n, x · xn−1 for odd n. How many calls does power(2, 62) make compared to a simple loop?
