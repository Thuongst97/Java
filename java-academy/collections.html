Lesson 12 · Core APIs & Functional Java

The Collections Framework

Lists, sets, maps and queues are the everyday data structures of Java. Learn what each interface promises, which implementation to pick, how to iterate and modify safely, and how to sort anything.

⏱ 65 min🎯 Intermediate🧩 Prerequisite: lesson 11

You will be able to

  • Choose between List, Set, Map, Queue and Deque
  • Pick the right implementation for the job
  • Modify collections while iterating — safely
  • Use modern Map methods like merge
  • Sort with Comparable and Comparator
  • Use immutable collections and defensive copies

12.1The big picture

Iterable<E> # anything usable in for-each └── Collection<E> ├── List<E> ordered, indexed, duplicates OK → ArrayList, LinkedList ├── Set<E> no duplicates → HashSet, LinkedHashSet, TreeSet └── Queue<E> processing order → ArrayDeque, PriorityQueue └── Deque<E> both ends (stack + queue) → ArrayDeque, LinkedList Map<K, V> # key → value; NOT a Collection → HashMap, LinkedHashMap, TreeMap
🧩
Program to the interface

Declare variables, parameters and return types with the interface — List<Expense> items = new ArrayList<>(); — so you can switch implementations without touching the rest of the code.

12.2Lists

ArrayList is backed by an array: get(i) is instant, appending is fast, inserting/removing in the middle shifts elements. LinkedList rarely wins in practice — use ArrayList by default and ArrayDeque for queues.

12.3Iterating and modifying safely

Changing a collection's structure while a for-each loop walks it throws ConcurrentModificationException. Use removeIf, an explicit Iterator, or build a new collection.

Keys must be well-behaved

Hash-based maps and sets rely on equals and hashCode. Use immutable keys (Strings, numbers, enums, records). If you mutate an object after using it as a key, the map can no longer find it.

12.6Queues, deques and priority queues

Don't use the legacy Stack and Vector classes — ArrayDeque is faster. offer/poll/peek return false/null on failure; add/remove/element throw.

12.8Immutable collections and defensive copies

List.of, Set.of, Map.of and copyOf create truly immutable collections and reject null elements. Collections.unmodifiableX only wraps — the underlying collection can still change.
