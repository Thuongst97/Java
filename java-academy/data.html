Data, Networking & Background Work

21.2SharedPreferences

A small key-value XML file per name. Reads are cached in memory; apply() writes asynchronously (use it), commit() blocks.

Jetpack DataStore is the modern, transactional replacement, designed around Kotlin coroutines/Flow (with RxJava and Guava adapters for Java). For a handful of Java-app settings, SharedPreferences remains simple and fine. Never store passwords or tokens in plain preferences.

21.3Room: a type-safe SQLite database

Room is an abstraction over SQLite. You write an entity (table), a DAO (queries) and a database class; Room's annotation processor checks your SQL against the schema at compile time and generates the implementation.

  • Threading: Room throws if you run a blocking query on the main thread. LiveData-returning queries are asynchronous; everything else goes through your I/O executor.
  • A typo in SQL is a compile error, e.g. “no such column: amount” — one of Room's biggest advantages over raw SQLite.
  • Custom types like LocalDate can be stored with a @TypeConverter; Spendly converts in its mapper instead, keeping the entity primitive.

Migrations

Changing an entity changes the schema. Increase the version and tell Room how to transform existing data — otherwise users' data is lost or the app crashes.

Commit the exported schemas/*.json files; MigrationTestHelper (room-testing) can then verify each migration in an instrumented test. Spendly's ExpenseDaoTest shows DAO tests against an in-memory database.

21.4Calling web APIs

Add <uses-permission android:name="android.permission.INTERNET" /> to the manifest. Network calls must run off the main thread (otherwise NetworkOnMainThreadException), and Android blocks plain http:// by default — use HTTPS.

📶
Networks fail — design for it

Handle no connection, timeouts, HTTP errors and malformed bodies; show a friendly message with a retry; cache the last good result. Spendly turns every failure into a Conversion.FAILED state the UI renders.

21.5JSON with Gson

🛡️
Gson and R8

Reflection-based mapping reads field names at runtime, but R8 renames fields in release builds. Annotate fields with @SerializedName("rates") or add -keep rules for your model classes (lesson 22). The tree model avoids the problem entirely.

21.6Notifications

  1. Create a channel (required since Android 8) — users control channels in system settings.
  2. Ask for permission on Android 13+ (POST_NOTIFICATIONS, a runtime permission — lesson 18's Activity Result API).
  3. Build and post with NotificationCompat; a PendingIntent opens your app on tap.

21.7WorkManager: reliable background work

Threads die with your process. Work that must happen eventually — syncing, uploading, a daily reminder — belongs in WorkManager: it persists requests in its own database, respects battery and network constraints, survives reboots and retries failures.

Periodic work has a minimum interval of 15 minutes and isn't exact to the minute — Android batches work to save battery. Inspect scheduled work in Android Studio's App Inspection → Background Task Inspector.

21.8Exercises

Exercise 1 — Remember the last query Easy

Save the search query in SharedPreferences when it changes and restore it when the list screen opens. Where should the read and write live so the Activity stays thin?

In the settings store (data layer); the ViewModel reads it in its constructor and writes on setQuery. The Activity just forwards text changes.

Exercise 2 — A new DAO query Medium

Add LiveData<List<CategoryTotal>> totalsByCategory(long from, long to) to ExpenseDao, where CategoryTotal is a small class with category and total fields, using GROUP BY. Write a DAO test for it.

Exercise 3 — Cache exchange rates Challenge

Add a rates table (base, target, rate, fetchedAtEpochMillis) with a migration from version 1 to 2. Make the rate service return a cached rate if it's less than 12 hours old, fetch otherwise, and fall back to a stale cached rate when offline. Unit-test the decision logic with an injected Clock.
