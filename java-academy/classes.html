Lesson 07 · Object-Oriented Java

Classes & Objects

Java is an object-oriented language: you model your problem as objects that bundle state (fields) with behaviour (methods). This lesson builds that skill from the ground up — constructors, encapsulation, static, the methods every object inherits, and immutability.

⏱ 60 min🎯 Intermediate🧩 Prerequisite: lessons 03–06

You will be able to

  • Write classes with fields, constructors and methods
  • Protect invariants with encapsulation
  • Choose the right access modifier
  • Use static fields, methods and factories
  • Implement toString, equals and hashCode correctly
  • Design immutable classes

7.1Classes are blueprints, objects are instances

A class describes what data an object holds and what it can do. new creates an object (an instance) on the heap from that blueprint. Each object has its own copy of the instance fields.

One file may contain several classes, but only one may be public. In Android Studio, give each class its own file — that's the convention.

7.2Constructors and this

A constructor runs when an object is created; it has the class's name and no return type. Use it to make sure every object starts in a valid state. this refers to the current object — needed when a parameter has the same name as a field. this(…) calls another constructor of the same class.

ℹ️
The default constructor

If you write no constructor, Java adds an empty no-argument one — that's why new Dog() worked above. As soon as you declare any constructor, the default one disappears. Fields you don't assign keep their defaults (0, false, null).

7.3Encapsulation: protect your invariants

Public fields let any code put an object into a nonsense state (account.balance = -1_000_000). Encapsulation means making fields private and exposing only methods that keep the object valid. The rules the object guarantees are its invariants.

💡
Don't generate setters by reflex

A getter/setter pair for every field is just a public field with extra steps. Expose operations that mean something in your domain (deposit, withdraw) and only the getters callers truly need. Android Studio's Generate (Alt+Insert) can write getters when you do need them.

Rule of thumb: start with private and widen only when needed. Fields: almost always private. Package-private is great for helpers that only one package uses — the Spendly app uses it to hide implementation classes.

7.5static: members that belong to the class

A static field has one copy shared by all instances; a static method runs without an object, so it cannot use this or instance fields. Use static for constants, counters, utility functions and factory methods.

⚠️
Static state on Android

Mutable static fields live as long as the app process — and Android kills and recreates processes at will. Never keep a static reference to an Activity, View or Context: it leaks the whole screen's memory. Lesson 20 shows the right place for long-lived state.

7.6toString, equals and hashCode

Every class extends java.lang.Object and inherits these three methods. The defaults are rarely what you want: toString() prints Point@1b6d3586, and equals() behaves like ==. For “value-like” classes, override them.

📜
The equals/hashCode contract

If you override equals, you must override hashCode so that equal objects return equal hash codes — otherwise HashMap and HashSet silently break. @Override asks the compiler to verify you really are overriding (a typo like equals(Point o) would otherwise create an unrelated overload). In lesson 09, records generate all three methods for you.

7.7Designing immutable classes

An immutable object can't change after construction — like String. Immutable objects are simpler to reason about, safe to share between threads and perfect as map keys. Recipe: final class, private final fields, no setters, and “withers” that return modified copies.

7.8Packages and imports

A package groups related classes and forms a namespace. The package line must be the first statement and must match the folder path. import lets you use a class by its short name.

java.lang (String, Math, System, Integer…) is imported automatically. Android Studio adds imports for you — Optimize Imports (Ctrl+Alt+O) removes unused ones.

7.9Object lifetime and garbage collection

Objects live on the heap as long as something can reach them through references. When nothing does, the garbage collector (GC) reclaims the memory automatically — there's no delete in Java. Your job is to avoid keeping references you no longer need (for example in static fields or long-lived lists): that's what a memory leak means in Java.

7.10Exercises

Exercise 1 — Rectangle Easy

Write a Rectangle class with private width and height, a constructor that rejects non-positive sizes, area(), perimeter(), isSquare() and toString().

Exercise 2 — Unique IDs Medium

Create a User class where every new user automatically gets the next id (1, 2, 3…) from a private static counter. Two users are equal if their ids are equal.

Exercise 3 — Immutable shopping cart line Challenge

Design an immutable CartLine(String product, int quantity, long unitCents) with withQuantity(int), totalCents(), equals/hashCode over all fields and a toString like 2 × Mug @ 8.50 = 17.00.
