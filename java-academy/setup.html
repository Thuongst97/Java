Toolkit: JDK & Android Studio

This whole course runs inside Android Studio. In this lesson you install it, discover the JDK hidden inside it, create a workspace where you can run plain Java programs for lessons 02–16, and wire up the Android SDK, an emulator and a real phone for lessons 17–22.

⏱ ~60 min (mostly downloads)🎯 Beginner💻 Windows · macOS · Linux

You will be able to

  • Explain what the JDK, JVM, IDE, SDK and Gradle each do
  • Install Android Studio on your OS
  • Run plain Java main methods inside Android Studio
  • Use javac, java and jshell from a terminal
  • Create an emulator and connect a real phone
  • Fix the most common setup errors yourself

1.2System requirements & virtualization

Android Studio, the Gradle daemon and the emulator each run in their own process. Practical numbers, slightly above the official minimums:

ResourceMinimumComfortable
OSWindows 10 64-bit · macOS 12+ · 64-bit LinuxWindows 11 · latest macOS · Ubuntu 22.04+
RAM8 GB16 GB or more
Free disk16 GB32 GB+ on an SSD
CPU64-bit x86_64 with virtualization, or Apple SiliconModern 8-core CPU

Check that hardware virtualization is enabled

The emulator runs a whole virtual phone; without hardware acceleration it is unusably slow. (Plain Java lessons don't need this — only lessons 17+.)

Open Task Manager → Performance → CPU and look for Virtualization: Enabled. If it is disabled, enable Intel VT-x / AMD-V (SVM) in your BIOS/UEFI. Then turn on the Windows Hypervisor Platform:

Nothing to do — macOS uses the built-in Hypervisor.framework. On Apple Silicon pick arm64-v8a system images later.

1.3Install Android Studio

Download the latest stable release from developer.android.com/studio. Avoid Canary/Beta builds while learning.

  1. Run android-studio-*-windows.exe and keep both components ticked (Android Studio, Android Virtual Device).
  2. Keep the default folder C:\Program Files\Android\Android Studio.
  3. Launch it from the Start menu.

Prefer winget? winget install Google.AndroidStudio

  1. Open the .dmg — pick the Mac with Apple chip build on M-series Macs.
  2. Drag Android Studio into Applications and launch it.

Prefer Homebrew? brew install --cask android-studio

The Setup Wizard

  1. Import settingsChoose Do not import settings on a fresh install.
  2. Install type: StandardIt installs the recommended SDK platform, build tools, platform-tools (adb) and the emulator.
  3. Accept the licensesClick each license on the left and choose Accept — Finish stays disabled until all are accepted.
  4. Wait for the downloads1–3 GB. When you see the Welcome screen, you're done.
⚠️
Remember your SDK path

Defaults: Windows %LOCALAPPDATA%\Android\Sdk, macOS ~/Library/Android/sdk, Linux ~/Android/Sdk. Avoid paths with spaces or non-ASCII characters.

1.4The JDK inside Android Studio

Android Studio ships with the JetBrains Runtime (JBR) — a complete OpenJDK 21 build. Gradle uses it to build your projects, and you can use it to compile and run plain Java too. Nothing else to install.

Check which JDK Gradle uses: Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK. It should say jbr-21 (“Embedded JDK”).

Use the bundled JDK from a terminal

Android Studio's built-in Terminal tool window (Alt+F12 / ⌥+F12) is handy, but java is only found if it's on your PATH. Point JAVA_HOME at the bundled JBR:

Then source ~/.zshrc and run java -version.

Then source ~/.bashrc and run java -version.

ℹ️
Want a standalone JDK instead?

That's fine too: install Eclipse Temurin 21 from adoptium.net (or winget install EclipseAdoptium.Temurin.21.JDK, brew install --cask temurin@21, sudo apt install openjdk-21-jdk). This course uses Java 21, the current long-term-support version that every tool supports; newer JDKs (25+) run all the examples too.

🧠
JDK, JRE, JVM — what's the difference?
JVM
The Java Virtual Machine: the program that loads .class files (bytecode) and executes them, compiling hot code to machine code on the fly.
JRE
JVM + standard library — enough to run Java. Modern JDKs no longer ship a separate JRE.
JDK
JRE + developer tools: javac, jshell, javadoc, jar, jdb… What you install as a developer.

1.5Create a workspace for plain Java

Android Studio is focused on apps, but it runs ordinary Java programs perfectly well. We'll create one project, JavaAcademy, that holds a pure Java module for lessons 02–16. Each lesson's examples become classes with a main method you run with one click.

  1. New projectOn the Welcome screen choose New Project → Phone and Tablet → No Activity. Name: JavaAcademy; Package name: com.example.javaacademy; Language: Java; Minimum SDK: API 26; Build configuration language: Kotlin DSL. Click Finish and wait for the first Gradle sync.
  2. Add a Java library moduleFile → New → New Module… → Java or Kotlin Library. Library name: lessons; Package name: com.example.lessons; Class name: Main; Language: Java. Click Finish.
  3. Raise the language level to Java 21Open lessons/build.gradle.kts and set both compatibility values to VERSION_21 (snippet below), then click Sync Now in the yellow banner.
  4. Write a main methodOpen lessons/src/main/java/com/example/lessons/Main.java and replace its contents with the program below.
  5. Run itClick the green ▶ in the gutter next to public static void main and choose Run 'Main.main()'. The output appears in the Run tool window. From now on, Ctrl+Shift+F10 (⌃+⇧+R on macOS) runs the file you're in.

On this website the example omits the package line so it can run in the browser. In Android Studio keep the package com.example.lessons; line the IDE generated at the top of each file — it must match the folder the file lives in.

JavaAcademy/ ├── app/ # an (empty) Android app module — used from lesson 17 ├── lessons/ # ← plain Java: lessons 02–16 │ ├── build.gradle.kts # java-library plugin, Java 21 │ └── src/main/java/com/example/lessons/ │ ├── Main.java │ └── l03/ Variables.java … # one package per lesson keeps things tidy ├── gradle/libs.versions.toml # version catalog (lesson 17) ├── settings.gradle.kts # include(":app", ":lessons") └── gradlew / gradlew.bat # Gradle wrapper
💡
Organise by lesson

Right-click com.example.lessons → New → Package and create l02, l03, … Inside, New → Java Class. Every class may have its own main; run whichever one you're working on. The Run tool window keeps a tab per run so you can compare outputs.

Programs that read keyboard input

When a program reads from System.in (lesson 02), click into the Run tool window and type there, then press Enter. To pass command-line arguments use Run → Edit Configurations… → Program arguments.

Quick experiments: scratch files & JShell

  • Scratch files: File → New → Scratch File → Java (Ctrl+Alt+Shift+Insert / ⌘+⇧+N) creates a throw-away file outside the project, with full code completion; run its main from the gutter.
  • JShell: the Java REPL. Type expressions and see results instantly — great for trying an API (more in the next section).

1.7Tour of the Android SDK & SDK Manager

Open Tools → SDK Manager. Two tabs matter:

SDK Platforms

One entry per Android version (API level), each containing android.jar — the APIs you compile against. Install the latest stable API; the final project uses compileSdk = 36.

SDK Tools

Make sure these are installed: Build-Tools, Platform-Tools (adb), Android Emulator and Command-line Tools (latest).

Sdk/ ├── build-tools/36.x.x/ # aapt2, d8, apksigner, zipalign ├── cmdline-tools/latest/ # sdkmanager, avdmanager ├── emulator/ # the Android Emulator ├── platform-tools/ # adb, fastboot ├── platforms/android-36/ # android.jar for API 36 └── system-images/ # emulator OS images

Put adb on your PATH (optional, handy)

🧠
compileSdk vs minSdk vs targetSdk
compileSdk
Which android.jar you compile against — the newest APIs you can call.
minSdk
The oldest Android version that can install your app.
targetSdk
The version whose behaviour you've tested against. Google Play requires a recent value.

1.8Create an Android Virtual Device (emulator)

  1. Open the Device ManagerView → Tool Windows → Device Manager, then + → Create Virtual Device.
  2. Pick hardwareA phone profile such as Pixel 8 or Medium Phone.
  3. Pick a system imageThe newest stable API with Google APIs or Google Play. ABI: x86_64 on Intel/AMD, arm64-v8a on Apple Silicon.
  4. Boot itPress ▶ next to the device. The first boot takes a minute; later boots use a Quick Boot snapshot.

1.9Run on a real Android device

  1. Settings → About phone → tap Build number seven times (“You are now a developer!”).
  2. Settings → System → Developer options → turn on USB debugging.
  1. Use a data cable (some cheap cables only charge).
  2. Accept “Allow USB debugging?” on the phone and tick Always allow.
  3. Windows: install the Google USB Driver (SDK Manager → SDK Tools) or your phone maker's driver if the device doesn't appear.
  1. Computer and phone on the same Wi-Fi; on the phone enable Developer options → Wireless debugging.
  2. In Android Studio's device dropdown choose Pair Devices Using Wi-Fi and scan the QR code from the phone.

If the state says unauthorized, unlock the phone and accept the debugging prompt.

1.10Your first Android app in Java

Let's prove the whole Android toolchain works end to end.

  1. New ProjectFile → New → New Project → Empty Views Activity. (The plain “Empty Activity” template uses Jetpack Compose, which is Kotlin-only. Views templates let you choose Java.)
  2. ConfigureName HelloAndroid, package com.example.helloandroid, Language: Java, Minimum SDK API 26, build configuration language Kotlin DSL.
  3. Wait for Gradle syncThe first sync downloads Gradle and dependencies and can take several minutes.
  4. RunPick your emulator or phone in the toolbar and press ▶ Run 'app' (Shift+F10 / ⌃+R). You'll see “Hello World!”.
  5. Change somethingEdit res/layout/activity_main.xml, change the text, and press Apply Changes (⚡) or Run again.

Don't worry about understanding this yet — lesson 17 dissects every file of an Android project and lesson 18 builds real screens.

  • Settings → Editor → General → Auto Import: tick Add unambiguous imports on the fly and Optimize imports on the fly.

The universal fix list

1. Sync Project with Gradle Files → 2. Build → Clean Project → 3. File → Invalidate Caches → Restart → 4. delete .gradle/ and build/ → 5. read the first error in the Build window.
