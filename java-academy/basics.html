Variables, Types & Operators

Programs remember things in variables, and in Java every variable has a type that the compiler checks. Learn the eight primitive types, how references differ, how to convert between types safely and how Java's operators behave — including the traps.

  • Explain primitives vs references and boxing

  • Predict the result of any operator expression

3.1Variables & constants

A variable is a named box that holds a value of a fixed type. Declare it with type name = value;. Add final to make it a constant: it can be assigned only once.

3.3Local type inference with var

Since Java 10 you can write var for local variables and let the compiler infer the type from the initialiser. The variable is still statically typed — var is not “any type”.

💡
When to use var

Use it when the type is obvious from the right-hand side (var list = new ArrayList<String>()) or very long. Prefer an explicit type when it documents intent (long total = sum(items)). Fields, parameters and return types always need explicit types.

3.4Primitives vs references, and boxing

Every type that is not one of the eight primitives is a reference type: String, arrays, and every class you write. A reference variable doesn't hold the object itself — it holds an arrow (address) pointing to an object on the heap, or the special value null meaning “points to nothing”.

Each primitive has a wrapper class (Integer, Long, Double, Character, Boolean…) so it can be used where an object is required, such as in collections. Java converts automatically: autoboxing (int → Integer) and unboxing (Integer → int).

🚨
Rule: compare objects with equals(), not ==

== on references asks “are these the same object?”. For values — Integer, String, anything — use .equals(). This bug hides in tests (small numbers are cached) and appears in production.

3.5Conversions, casting & overflow

Widening conversions (to a bigger type) happen automatically: int → long → double. Narrowing conversions may lose information, so you must ask for them explicitly with a cast (type).

⚠️
Overflow is silent

Integer arithmetic wraps around without any error. If overflow would be a bug (money, sizes), use long or the exact methods Math.addExact, Math.multiplyExact, which throw ArithmeticException instead of returning garbage.

3.7The Math class & floating-point pitfalls

💸
Never store money in a double

double cannot represent 0.1 exactly. For money use BigDecimal (created from a String), or store whole cents in a long — which is exactly what the Spendly app in the final project does.

🎲
Random numbers

Math.random() returns a double in [0, 1). Prefer java.util.random.RandomGenerator.getDefault().nextInt(1, 7) (Java 17+) or new java.util.Random().nextInt(6) + 1 for a die roll; on Android both work.

Exercise 1 — Temperature converter Easy

Convert 36.6 °C to Fahrenheit (F = C × 9 / 5 + 32) and print it with one decimal place. Then make the formula use only int values for 37 °C — why is the result different from 98.6?

Exercise 3 — Spot the overflow Challenge
