Lesson 08 · Object-Oriented Java

Inheritance, Polymorphism & Interfaces

Write code that works with any kind of shape, payment method or click listener. Inheritance and interfaces let one piece of code handle many types — the foundation of every Android API you will use.

⏱ 60 min🎯 Intermediate🧩 Prerequisite: lesson 07

You will be able to

  • Extend classes and call super
  • Override methods correctly with @Override
  • Explain dynamic dispatch (polymorphism)
  • Use abstract classes and the template method
  • Design interfaces with default methods
  • Prefer composition when inheritance doesn't fit

8.1extends and super

A subclass inherits the fields and methods of its superclass and can add its own. The relationship must read naturally as “is a”: a SavingsAccount is an Account. A subclass constructor must call a superclass constructor first — explicitly with super(…) or implicitly with the no-arg one.

Java has single inheritance of classes: a class extends exactly one class (Object if you don't say). It may implement many interfaces.

8.2Overriding methods

A subclass overrides a method by declaring one with the same signature. Always add @Override: the compiler then errors if you misspell the name or get a parameter wrong. Call the parent version with super.method().

8.3Polymorphism and dynamic dispatch

A variable's declared (static) type decides which methods you may call; the object's runtime type decides which implementation runs. That's dynamic dispatch, and it lets one loop handle every subtype — including ones written next year.

🤖
You'll see this everywhere on Android

MainActivity extends AppCompatActivity and overrides onCreate; the framework holds it as an Activity and calls onCreate() — your version runs. Every RecyclerView.Adapter, Worker and ViewModel you write in lessons 18–23 works the same way.

8.4Abstract classes and the template method

An abstract class can't be instantiated; it exists to be extended. It may declare abstract methods (no body) that every concrete subclass must implement, alongside normal fields and methods. A classic use is the template method pattern: the base class fixes the algorithm's steps, subclasses fill in the details.

8.5Interfaces

An interface is a pure contract: “anything that implements me can do X”. A class can implement many interfaces, and unrelated classes can share one. Since Java 8 interfaces may also contain default methods (with a body), static methods and, since Java 9, private helpers.

👂
Interfaces on Android: listeners

View.OnClickListener is an interface with one method, onClick(View v). When you write button.setOnClickListener(v -> save()) you pass an implementation of it. Callbacks, adapters, DAOs and repositories in this course are all interfaces.

Default to interfaces. They keep types flexible and testable (you can substitute a fake implementation — lesson 16). Add an abstract base class later if implementations share a lot of code.

8.7Composition over inheritance

Inheritance couples a subclass tightly to its parent's implementation. If “is a” doesn't hold, or you only want to reuse some behaviour, compose: hold the other object in a field and delegate to it.

🧩
Why this matters

If Playlist extends ArrayList, callers could bypass add with addAll or set and break your no-duplicates rule. Composition exposes only the operations you choose, and passing the Logger in the constructor (dependency injection) lets a test supply a fake. Lesson 20 uses exactly this to build Android repositories.

8.8Exercises

Exercise 1 — Shapes Easy

Create an abstract class Shape with abstract double area() and a concrete describe(). Implement Circle and Square, then print the total area of an array of mixed shapes.

Exercise 2 — Discount strategies Medium

Define interface Discount { long apply(long cents); } with implementations NoDiscount, PercentOff(int percent) and FixedOff(long cents) (never below 0). Add a default Discount then(Discount next) that chains two discounts.
