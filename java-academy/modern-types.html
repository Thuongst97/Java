Lesson 09 · Object-Oriented Java

Records, Enums, Sealed Types & Pattern Matching

Modern Java (16–21) lets you model data with a fraction of the code: records for plain data, enums for fixed sets, sealed types for closed hierarchies, and pattern matching to take them apart safely. Plus the nested and anonymous classes you'll meet in older Android code.

⏱ 55 min🎯 Intermediate🧩 Prerequisite: lesson 08

You will be able to

  • Replace boilerplate classes with records
  • Write enums with fields and behaviour
  • Model closed hierarchies with sealed
  • Use pattern matching in instanceof and switch
  • Deconstruct records with record patterns
  • Read nested, inner and anonymous classes

9.1Records: data classes in one line

A record (Java 16) is a transparent, immutable carrier of data. From the header, the compiler generates private final fields, a constructor, accessor methods (name(), not getName()), equals, hashCode and toString.

📏
Record rules

Records are implicitly final, can't extend another class (they may implement interfaces), and can't declare extra instance fields. Use them for values: DTOs, results, keys, events, UI state. Use a normal class when you need mutable state or encapsulated invariants that change over time.

9.2Enums: a fixed set of constants

An enum defines a type with a fixed set of named instances. Unlike int constants, enums are type-safe, printable and can carry fields and methods.

💾
Persist names, not ordinals

ordinal() changes if someone reorders the constants. When saving an enum to a database or preferences, store name() and read it back with valueOf — the Spendly app does exactly this.

9.3Sealed classes and interfaces

A sealed type (Java 17) lists exactly which types may extend it with permits. The hierarchy is closed, so the compiler knows every possible case — perfect for modelling results, UI states and commands. Each permitted subtype must be final, sealed or non-sealed (records are implicitly final).

Add a fourth state, record Empty() implements LoadState, to the permits list and the switch stops compiling until you handle it. That compile error is the whole point: no forgotten cases.

Order matters

Cases are tried top to bottom. A more general pattern before a specific one (case Integer i before case Integer i when i < 0) is a compile error: the second could never match (it is “dominated”).

🤖
On Android

Records, sealed types, text blocks, switch expressions and instanceof patterns (Java 16/17) are supported in Android apps built with a current Android Gradle Plugin and JavaVersion.VERSION_17 — the final project uses records. Newer features such as switch pattern matching (Java 21) depend on your AGP version; check Java versions in Android builds before relying on them in an app.

💧
The classic Android leak

An inner or anonymous class inside an Activity silently keeps a reference to that Activity. If such an object outlives the screen (a background task, a static field, a delayed Handler message) the whole Activity and its views can't be garbage-collected. Prefer static nested classes and lifecycle-aware components (lesson 20).

9.7Exercises

Exercise 1 — Planets Easy

Create enum Planet with MERCURY, EARTH and JUPITER, each with its surface gravity in m/s² (3.7, 9.81, 24.79). Add weight(double massKg) and print how much a 70 kg person weighs (in newtons) on each.

Exercise 2 — A Result type Medium

Model the result of parsing an age as sealed interface ParseResult with records Ok(int value) and Err(String reason). Write parseAge(String) (0–150 only) and print each result with a switch.

Exercise 3 — Expression evaluator Challenge

Represent arithmetic expressions as a sealed hierarchy: Num(double), Add(Expr, Expr), Mul(Expr, Expr), Neg(Expr). Write recursive eval and show methods using record patterns. Evaluate -(2 + 3) * 4.
